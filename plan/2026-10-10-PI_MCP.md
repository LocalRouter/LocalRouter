## Findings

Sources: https://pi.dev/docs/latest/mcp (same text as
`packages/coding-agent/docs/mcp.md` in https://github.com/earendil-works/pi),
https://pi.dev/docs/latest/configuration, and upstream source
`packages/coding-agent/src/extensions/mcp/config.ts`,
`packages/coding-agent/src/core/mcp-servers.ts`,
`packages/coding-agent/src/extensions/mcp/runtime.ts`,
`packages/coding-agent/src/core/resolve-config-value.ts`,
`packages/coding-agent/src/config.ts`, `packages/coding-agent/CHANGELOG.md`.

- **Built in, not third-party.** MCP support ships as a built-in extension
  (`builtin:mcp`) since Pi 0.99.0 (2026-09-29, changelog: "Added codemode, tool
  search, and MCP support as built-in extensions"). Current release 1.1.0. It
  is on by default; users can turn it off with `"extensions": ["-builtin:mcp"]`,
  `pi config`, or `--no-mcp`. A third-party extension that registers `/mcp`
  (e.g. `pi-mcp-adapter`) replaces it and then `mcp.json` is not read.
- **Config file.** User-level `<agent-dir>/mcp.json` (`~/.pi/agent/mcp.json`,
  agent dir from `getAgentDir()`: `$PI_CODING_AGENT_DIR` with `~` expansion,
  else `~/.pi/agent`). Project `.pi/mcp.json` only in trusted projects; a
  project entry with the same name replaces the user entry.
- **Shape.** `{ "mcpServers": { "<name>": { ... } } }`, the shape other MCP
  clients use. Parsed with plain `JSON.parse` (no comments). The root must be
  an object and `mcpServers` an object; invalid entries are reported and
  skipped without affecting others. Server names: `[A-Za-z0-9_-]+`.
- **Transports.** stdio (`command`, `args`, `env`, `cwd`) and Streamable HTTP
  (`url`, `headers`, `oauth`, `auth`). `type` is optional (`stdio`, `http`,
  `streamable-http`); a `url` selects HTTP. Legacy SSE is rejected.
- **Auth header.** `headers` is a string map; `"Authorization": "Bearer …"` is
  the documented example. With an `Authorization` header (any case) Pi does
  not attempt OAuth. Header values go through Pi's config-value resolution:
  `${NAME}`/`$NAME` are environment variables and a value starting with `!` is
  a shell command. LocalRouter secrets are `lr-` + base64url, so
  `Bearer lr-…` is passed literally.
- **Per-entry user settings.** `enabled`, `exposure` (default `codemode`),
  `toolExposure`, `timeout`, `description`. Pi's `/mcp` UI saves exposure and
  enabled-state changes into the file that defines the server, keeping other
  content.

## Decision

Pi connects to an HTTP MCP server with a bearer header from a documented,
built-in config file, so the integration writes it, like OpenCode and Droid.

- `PiPaths` gains `mcp = <agent-dir>/mcp.json`; `$PI_CODING_AGENT_DIR` is
  honoured through the existing `agent_dir()`.
- MCP gateway mode (`should_sync_mcp`) writes `mcpServers.localrouter` with
  `url` = LocalRouter's base URL and `headers.Authorization = Bearer <secret>`.
  An existing `localrouter` entry is merged, not replaced: LocalRouter owns
  `url` and the `Authorization` header and removes keys that would select
  another transport or auth (`type`, `command`, `args`, `env`, `cwd`,
  `oauth`, `auth`, other-case `authorization` headers). The user's
  `enabled`, `exposure`, `toolExposure`, `timeout`, `description` and other
  headers survive, so choices made in Pi's `/mcp` are not reset by re-syncs.
- Other modes remove `mcpServers.localrouter` when present; other servers and
  top-level keys (e.g. `autoEnableCodemode`) are untouched. A missing
  `mcp.json` is never created just to remove an entry.
- Strict parsing: `mcp.json` is validated with the other two files before any
  write; a malformed file or a non-object `mcpServers` is an error and
  nothing is written. Unchanged files are not rewritten.
- `configure_permanent` (no mode context) writes both LLM and MCP, matching
  OpenCode.
- Template: `supportsMcp: true`, `defaultMode: 'both'` (like the other
  MCP-capable coding agents), and an `mcpConfigFile` with the `mcp.json`
  snippet, the Pi version requirement (0.99+) and the `/reload` hint for
  running sessions. `docsUrl` stays on the models page (main setup).
- No Tauri command signature or type changes; the demo mock lists `mcp.json`
  among Pi's modified files.

## Tests
`pi.rs` unit tests with temp agent and backup directories (no real home):
MCP entry written in gateway mode; other servers and top-level keys kept;
user exposure/enabled/description/extra headers kept across re-sync while
conflicting transport keys are dropped; identical re-sync rewrites nothing;
MCP-off removes only `localrouter`; MCP-off without `mcp.json` creates
nothing; malformed `mcp.json` (bad JSON, non-object root, non-object
`mcpServers`) is refused in every mode with no file touched; MCP-only mode
writes the MCP entry and removes the LLM provider and LocalRouter-owned
defaults; secret rotation rewrites only `mcp.json` (with a backup in the temp
backup dir); a non-object `localrouter` entry or `headers` value is rebuilt;
the `configure_permanent` path writes both LLM and MCP.

  `write_config_at`, is exercised by the tests above (28 `pi.rs` tests).
- Bug hunt: removals use `retain`, so with serde_json's `preserve_order`
  (enabled for the workspace by `lr-providers`) the user's other servers and
  keys keep their order (`Map::remove` would swap-remove). `"mcpServers": null` is rejected,
  as Pi itself rejects it. Header values go through Pi's `$`/`!` resolution;
  `Bearer lr-<base64url>` contains neither, so it is sent literally.

## Known limits
- A project `.pi/mcp.json` entry named `localrouter` replaces the user-level
  one in that project (Pi's documented precedence); LocalRouter does not
  touch project files.
- The entry has no effect when the user installs a third-party extension
  that registers `/mcp` (e.g. `pi-mcp-adapter`, which replaces the built-in
  support and does not read `mcp.json`), or disables built-in MCP with
  `"extensions": ["-builtin:mcp"]` or `--no-mcp`.
- Pi's default `exposure` is `codemode`: LocalRouter's tools are reached from
  codemode scripts unless the user picks `direct`/`deferred` in `/mcp`, which
  re-syncs keep.
