## Scope since v0.0.190

Merged branches (each validated on its own branch, then together on master):

- Streaming request pipeline, completing the plan in
  `plan/2026-11-16-STREAMING_REQUEST_PIPELINE.md`:
  - Phase 2: WebSocket messages stream frame by frame (incl. pass-through and late `model`
    held in spill).
  - Phase 3: encrypted disk spill, Secret Scan Ask hold-on-finding, model gate and model-Ask
    preview, strict streaming, length-required framing (learned hosts persisted).
  - Phase 4: GuardRails hold over spill; reverse-proxy LLM paths stream; response capture keeps
    head and tail and usage is parsed incrementally (fixes lost usage on responses > 1 MiB).
  - Phase 5: configurable native body limit, large-body memory budget, single-copy JSON ingress,
    fail-closed secret boundary.
  - Final cleanup: strict masking whenever output is held, one shared `prepare_stream`, zstd
    re-encode on both proxies and both paths, real-TLS WebSocket e2e.
- Rate limits and accounting: atomic admission for non-chat endpoints and for proxied requests,
  strategy shares held until metrics are written, Retry-After on client and strategy 429s,
  refusals no longer counted as failed requests, cached tokens no longer double counted,
  signed (HMAC) request-trace headers so a request looping through LocalRouter twice is
  counted once.
- Secret Scan coverage: embeddings, moderations, rerank, search, OCR, images, speech, video and
  token counting are scanned; access, model-permission and rate-limit refusals happen before any
  Secret Scan popup; refused requests are masked before the monitor keeps them.
- MCP gateway: sampling passthrough limits and capability checks, sessions held alive by open
  streams, unknown sessions answered 404 (STDIO bridge re-initializes), resubscribe after
  reconnect, cancellations for reads and prompts, `tools/call` up to 24 h, configured roots.
- MCP-via-LLM and Responses: guardrail-gated streaming, per-call usage, joined chat reply,
  persisted hidden history and pending mixed executions, classified streaming errors, the full
  Responses event sequence.
- Router/providers: `n > 1` on every provider, Gemini batch embeddings, `reasoning_tokens`,
  video cancel/delete matrix, OAuth Basic credentials form-urldecoded, moderations row from the
  GuardRails config.
- Skills, config, downloads: extraction budgets and atomic installs (data-dir extractions,
  cross-process locks, atomic exchange), model download manifests, config save/reload
  three-way merge, proxy-sync state file.
- Cross-platform: Linux and Windows clippy clean.
- Website: Terms of Service and Privacy Policy pages (by the user).

Behaviour changes users may notice are listed in each branch plan; the most visible:
a one-time keychain entry `LocalRouter-TraceSigning` (macOS may prompt once); unknown MCP
session ids get 404; image and moderation requests count against rate limits; auto-routing
answers a full strategy limit with 429 instead of 502; zstd request bodies stay zstd when
rewritten.
