## Implementation review

Implemented opt-in strategy settings and a maximum of 4,096 process-local sessions with bounded idle expiry. State keys bind client, full strategy/policy, provider revision, pricing overrides, explicit mode, endpoint and a private process salt. Pins stay within their route group and recheck eligibility. Reset replaces an entry, so old handles cannot repopulate a new session; classifier generations reject stale in-flight results. A private per-turn marker applies reset once across classification, routing and MCP continuation, is rejected at public ingress and is removed before upstream dispatch.

Session IDs come from the explicit body namespace or supported session headers, never the user field. Classifier reuse requires an identical bounded routing context and current configuration; successful classifications alone are cached, with zero new latency/spend on reuse. Strict continuation validates the original pin before classification and prohibits model/provider migration. Known upstream gateways cannot guarantee inference-provider continuity, so strict requests fail closed and direct the caller to a direct provider/model. Signed/encrypted input cannot silently start an unbound automatic conversation.

The provider cache-key surfaces are native OpenAI Chat/Responses and LLM Gateway chat. Derived keys are private to a client/session/process; explicit caller keys retain their intended upstream meaning. Raw session IDs and internal control markers are consumed locally. All new settings default off. Provider prompt reads/writes and uncached tokens are reported separately from response caching; net savings use available model rates, remain unknown with missing rates and can be negative for write premiums. Legacy fixed-discount claims were removed. Native OpenAI/compatible transports now retain detailed token usage, including reasoning/cache details, and the usage ledger records cache writes. Streaming snapshots are deduplicated per upstream call.

UI, TypeScript and demo contracts cover settings, monitoring and preview. The preview command accepts an explicit client scope and optional session input; cached preview never allocates/resets a live session, refreshes its expiry or performs network IO. Its candidate order agrees with live affinity preference. Configuration fingerprints include session settings for later replay reproducibility.

Coverage includes isolation, mode/config/endpoint/restart changes, expiry, bounded eviction, reset/reclassification races, cache-only mode, no paid classification on invalid strict continuation, read-only/live preview parity, header/body normalization, native and compatible transport usage, private/explicit cache keys, unknown prices/write premiums and streaming cost deduplication.
