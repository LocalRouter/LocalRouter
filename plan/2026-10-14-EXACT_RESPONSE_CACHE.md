The cache is opt-in and local memory only. A hit must never authorize access that a fresh request would be denied. Cached data cannot resurrect a disabled model, weaken gateway privacy controls, bypass an approval/scanner, or silently reuse another client's response. Semantic matching, persistent prompt storage and synthesized streaming playback are excluded from this first implementation.

Use the shared router/server pipeline rather than a parallel proxy policy stack. Native classification caching must preserve the typed decision contract; unsupported/opaque state is excluded explicitly. Replay comparisons bypass this cache so experiments measure newly invoked targets. A cached result can retain its original served tokens for display while clearly reporting zero new inference spend; previous-call cost is an estimate of avoided spend, not a new provider invoice or guaranteed savings.

## Implementation review

Per-strategy cache settings are opt-in and default off. Configuration load and the Tauri update command validate TTL 1–3600 seconds, 1–1024 entries and 1 KiB–32 MiB per client. The shared cache caps retained serialized responses at 64 MiB / 4096 entries globally and 1 MiB per response. Background maintenance expires payloads, and clear invalidates pending writes. Cached payloads are never persisted.

Authentication supplies a process-salted credential fingerprint that callers cannot inject. Keys bind the client, credential, current configuration/provider revision, resolved provider/model, ingress endpoint and full request serialization, preserving wire ordering where significant. Only normal authenticated gateway requests qualify. Session/replay/MCP/tool/stream requests, known search models and unsupported extensions are excluded. Native Responses envelopes retain provider item/continuation identities and deliberately bypass this first cache implementation; ordinary text Responses translations and native typed decisions are supported.

A completed upstream response produces only a bounded, expiring payload-free pending ticket. The HTTP success path commits after approvals/final checks and decision-wire validation; rejected/cancelled requests cannot populate the payload cache. Configuration/provider fingerprints are checked again at commit. Hits do not consume a dispatch slot, provider token allowance, provider account-ledger request or latency observation. They retain served usage as provenance, emit fresh local identities and explicitly report zero new spend/billed tokens for the resolved model call. Current routing classifiers and safety checks can still have separate spend, covered by an auto-routing billing fixture. Previous-call cost references remain estimates, with unknown prices preserved. Normal client-request quotas still apply, and cached hits still require current time-based model approval.

The client Models settings include enable/limits, statistics and clear controls. The request monitor displays cached-response provenance and separates original served usage from new billing. Response adapters preserve the receipt across Chat, Completions, Responses and native decisions. Tauri parameters/types and website mocks are synchronized. Review also corrected the replay current-policy command to use the ConfigManager state type actually registered by the app.

Native key metadata lives outside the serialized request body, so vendor fields cannot collide with internal sidecars; cache controls are normalized in both decision representations so refresh replaces the normal entry.
